# WASHFLOW

Русскоязычное mobile-first PWA для iPhone: помощник на мойке самообслуживания.
Один раз добавляете оборудование и свою химию → нажимаете **«Начать мойку»** → получаете
пошаговый сценарий: что взять, **сколько миллилитров химии и воды налить**, как нанести,
сколько выдержать и как смыть. Без калькуляторов, без регистрации, работает офлайн.

## Запуск

```bash
npm install
npm run dev          # http://localhost:5173 (с телефона в той же сети — адрес из вывода --host)
npm test             # модульные тесты (Vitest)
npm run test:e2e     # e2e в мобильном Chromium (собирает прод-сборку и поднимает preview)
npm run build        # каталог → проверка типов → сборка PWA в dist/
npm run preview      # раздача dist/ на :4173
```

Установка на iPhone: откройте собранную версию в Safari по HTTPS → «Поделиться» →
«На экран „Домой“». После первой загрузки приложение работает без сети (service worker
кэширует всё, включая каталог и шрифты), данные хранятся в `localStorage` устройства.

## Что внутри

| Экран | Что делает |
|---|---|
| Приветствие | первый запуск: «Настроить под себя» или демо-профиль |
| Главная | авто, «Начать мойку», моё оборудование, моя химия, готовый сценарий, продолжение незавершённой мойки |
| Сценарий мойки | Быстрая / Стандартная / С защитой, степень загрязнения, диски и антимошка, список этапов |
| Пошаговая мойка | один шаг на экран, крупные цифры мл, таймер выдержки (звук + вибрация), назад/далее/пропустить (смыв химии пропустить нельзя), общее время, экран не гаснет (Wake Lock), прогресс переживает перезагрузку |
| Итог | расход концентрата и списание из остатков |
| Моё оборудование | ручной распылитель, пеногенератор, пенокомплект АВД, ведро, триггер; номинал и объём заливки |
| Моя химия | остаток «X мл из Y мл», фильтры по фазам |
| Каталог | поиск по бренду/названию (в т. ч. кириллицей: «черри бомб»), фильтры, избранное, «с методикой» |
| Карточка средства | методика отдельно по каждому способу нанесения, выдержка, шаги, ограничения, источник и дата проверки |
| Профиль | авто, импорт карточек JSON, синхронизация с облаком, резервная копия, демо-профиль, история |

### Как считаются дозировки (`src/domain`)

- `dilution.ts` — `1:X` (по умолчанию 1 часть концентрата + X частей воды; вариант «1 часть в X частях раствора» хранится явно), `мл/л` воды или раствора, `%`, «без разведения». Точка внутри диапазона производителя выбирается по степени загрязнения и **никогда не выходит за диапазон**; после округления концентрация проверяется ещё раз.
- `scenario.ts` — подбирает средство под каждую роль (диски → 1 фаза → 2 фаза → защита) и способ нанесения под имеющееся оборудование. Объём раствора — по типу ёмкости и кузову; для средств без разведения — только по расходу, указанному производителем (иначе объём не выдумывается).
- Безопасность: каждое средство в отдельной ёмкости; если одна ёмкость нужна двум средствам, второй раствор готовится после смыва и с промывкой ёмкости; после каждой химии обязательный смыв. Нет подтверждённой методики или подходящего оборудования → **рецепт не выводится**, показывается честное сообщение.
- Объём упаковки химии хранится отдельно от объёма ёмкости для раствора.

### Каталог

- Исходники: `catalog-src/<бренд>.json` — у каждой методики способ нанесения, дозировка как в источнике (`dilutionText`), нормализованная дозировка, выдержка, шаги, ограничения, `sourceUrl`, `checkedAt`, цитата-доказательство.
- `npm run catalog:build` валидирует (zod) и собирает `src/data/catalog.json`; `npm run catalog:report` печатает отчёт по брендам.
- `npm run catalog:import -- file.json` — импорт/обновление бренда: слияние по `id`, методика заменяется только более свежей `checkedAt`.
- В приложении: Профиль → «Импорт карточек (JSON)» в том же формате; «Своё средство» — ручной ввод с этикетки (помечается «введено вами»).
- Схема запрещает `verified` без методики и `unverified` с дозировками.

### Supabase (необязательно)

Базовая мойка работает без Supabase и без входа. Облако нужно только для общего
обновляемого каталога:

1. Создайте проект, выполните `supabase/migrations/0001_catalog.sql` (RLS: все читают только `published`, писать может только `service_role`).
2. Скопируйте `.env.example` → `.env`, заполните `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` (только anon key).
3. Публикация каталога: `SUPABASE_URL=… SUPABASE_SERVICE_ROLE_KEY=… npm run catalog:push` (service-ключ только локально/в CI, не в `VITE_*`).
4. В приложении: Профиль → «Обновить из облака». Пришедшие карточки снова проходят валидацию.

Личные данные (авто, оборудование, химия) в облако не отправляются.

## Демо-профиль

Профиль → «Загрузить демо-профиль»: Mazda 6 (седан), Marolex Industry Ergo 2 л,
Shine Systems DelicateWash, CherryBomb, FastQuartz. Дозировки берутся из каталога
(официальные страницы shinesystems.ru); если бы методики не было, рецепт не показывался бы.

## Важно

Цифры и упаковки на макетах в `screenshots/` демонстрационные и не используются как
источник дозировок. Данные каталога собраны с официальных страниц производителей на дату
`checkedAt`; производитель может изменить рекомендации — сверяйтесь с этикеткой.
